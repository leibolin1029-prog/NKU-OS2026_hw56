## 一、实验整体逻辑线

Lab 4 的代码分布在三条线上：物理内存与页表（`kern/mm`）、进程与线程（`kern/process`）、调度与切换（`kern/schedule`）。它们不是彼此独立的练习，而是一条从“内核启动”到“第一个内核线程运行”的完整链路。下面按启动顺序说明。

**（1）启动阶段先建立“能跑的映射”。** `kern/init/entry.S` 中的 `boot_page_table_sv39` 是一张 4 KB 的顶层页表，前 511 项为 0，最后一项是 `(0x80000 << 10) | 0xcf`，即把虚拟地址 `0xFFFFFFFFC0000000` 起的 1 GB 直接映射到物理地址 `0x80000000`，权限为 V/R/W/X/U/A/D。内核被链接在 `0xFFFFFFFFC0200000`（`KERNBASE`），正好落在这个巨页里，所以在 `satp` 尚未切换、页表尚未完整建立时，取指与访存仍然可用。设置 `sp = bootstacktop` 后跳入 `kern_init`。

**（2）`pmm_init` 建立物理页管理与内核页表。** `kern_init` 依次调用 `dtb_init`、`cons_init`，随后进入 `pmm_init`：

1. `init_pmm_manager()` 把 `pmm_manager` 指向 `default_pmm_manager`（本实验在 `default_pmm.c` 中回填的 Best-Fit 管理器）。
2. `page_init()` 从 DTB 得到物理内存 `0x80000000`、大小 128 MB；计算 `npage`，把 `Page` 数组紧跟在链接符号 `end` 之后；先把 `[nbase, npage)` 的所有页标记为 `PageReserved`，再把 `Page` 数组末尾到 DRAM 顶端之间的页交给 `init_memmap` 挂入空闲链表。
3. `check_alloc_page()` 调用 `pmm_manager->check()`，即 `best_fit_check()`，验证分配、释放、分裂、合并与计数。
4. 设置 `boot_pgdir_va = boot_page_table_sv39`、`boot_pgdir_pa = PADDR(boot_pgdir_va)`。
5. `check_pgdir()` 用刚实现的 `page_insert` / `page_remove` 在低地址 `0x0`、`PGSIZE`、`2*PGSIZE` 上做映射、重映射、撤销，检查 `pte2page`、引用计数、`PTE_U/PTE_W` 位与 `nr_free` 是否回到初值。
6. `check_boot_pgdir()` 在 `0x100` 与 `0x100+PGSIZE` 上把同一物理页映射两次，做 `strcpy`/`strcmp`，确认页表确实生效。
7. `kmalloc_init()` 初始化 SLOB 分配器，为 `alloc_proc` 提供内核堆。

**（3）`vmm_init` 只验证 VMA 结构。** Lab 4 还不处理用户态缺页，`vmm_init` 中的 `check_pgfault` 被注释掉，实际只运行 `check_vma_struct`，验证 `mm_create`、`vma_create`、`insert_vma_struct` 的链表插入与边界查找。这一部分为后续实验预留接口。

**（4）`proc_init` 创建 0 号与 1 号内核线程。** 此时 `current` 还指向“正在执行 `kern_init` 的执行流”，`proc_init` 用 `alloc_proc()` 为它分配 PCB，填写 `pid = 0`、`state = PROC_RUNNABLE`、`kstack = bootstack`、`need_resched = 1`、`name = "idle"`，并令 `current = idleproc`。注意 `idleproc` **没有**被插入 `proc_list`：它是调度器的兜底线程，不应该像普通线程那样参与 FIFO 轮转。随后 `kernel_thread(init_main, "Hello world!!", 0)` 创建 `initproc`，`find_proc(pid)` 找到它并命名为 `"init"`。

**（5）时钟与中断打开后进入 `cpu_idle`。** `clock_init()` 设置下一次时钟中断，`intr_enable()` 打开 S 态中断，然后调用 `cpu_idle()`。`idleproc->need_resched` 为 1，`cpu_idle` 立刻调用 `schedule()`；`schedule` 从 `proc_list` 中选中 `initproc`，`proc_run` 把 `satp` 切换为 `initproc->pgdir`（内核线程共享 `boot_pgdir_pa`），刷新 TLB，调用 `switch_to`。

**（6）第一次切入新线程。** `switch_to` 把 `idleproc` 的 `ra`、`sp`、`s0`–`s11` 存进 `idleproc->context`，从 `initproc->context` 恢复 `ra = forkret`、`sp = initproc->tf`，`ret` 跳到 `forkret`。`forkret` 调用 `forkrets(current->tf)`，后者执行 `move sp, a0; j __trapret`；`__trapret` 的 `RESTORE_ALL` 从 `sp` 指向的 `trapframe` 恢复 `sstatus`、`sepc`、全部通用寄存器，最后 `sret` 跳到 `tf->epc = kernel_thread_entry`。`kernel_thread_entry` 执行 `move a0, s1; jalr s0`，于是 `init_main(arg)` 开始运行；`init_main` 返回后 `jal do_exit`，Lab 4 中 `do_exit` 仍是 `panic` 占位，内核停在监控器。

这条链路把 Lab 2 的页表、Lab 3 的 trapframe 和 Lab 4 的线程创建串在一起：**页表让虚拟地址可用，trapframe 让“新线程的第一次运行”表现得像一次从中断返回，调度器则决定什么时候发生这次返回。**

### 2.1 物理页管理器：把 lab2 的 Best-Fit 回填到 `default_pmm.c`

Lab 4 的骨架删除了 lab3 的 `best_fit_pmm.c`，但 `default_pmm.c` 顶部仍保留 `#include <best_fit_pmm.h>`，这个头文件在 lab4 中并不存在。如果直接编译会失败；同时 `default_pmm_manager` 也没有定义。回填方案是：把 lab2 的 Best-Fit 实现直接写进 `default_pmm.c`，函数改名为 `default_*`，并导出管理器实例。

Best-Fit 的核心不变量是：`free_list` 按物理页号升序排列，每个空闲块的**首页**设置 `PageProperty`，`property` 记录块长；块内其余页的 `property` 为 0。分配时遍历整个链表，选择 `property >= n` 且 `property` 最小的块；若块比请求大，把尾部 `property - n` 页分裂出来重新挂回链表。释放时先清 `flags`、`ref`，再按地址插入有序链表，最后分别与前驱、后继合并。

```c
static struct Page *
default_alloc_pages(size_t n) {
    assert(n > 0);
    if (n > nr_free) {
        return NULL;
    }
    struct Page *best = NULL;
    list_entry_t *le = &free_list;
    while ((le = list_next(le)) != &free_list) {
        struct Page *p = le2page(le, page_link);
        if (p->property >= n && (best == NULL || p->property < best->property)) {
            best = p;
        }
    }
    if (best == NULL) {
        return NULL;
    }
    list_entry_t *prev = list_prev(&(best->page_link));
    list_del(&(best->page_link));
    if (best->property > n) {
        struct Page *p = best + n;
        p->property = best->property - n;
        SetPageProperty(p);
        list_add(prev, &(p->page_link));
    }
    nr_free -= n;
    ClearPageProperty(best);
    return best;
}
```

这里有一个容易写错的细节：`list_add(prev, &(p->page_link))` 是“插在 `prev` 之后”。`prev` 是 `best` 被删除前的前驱，所以分裂出的尾部块仍然位于 `prev` 与原 `best` 之间，链表保持升序。`best_fit_check()` 会分配 5 页、释放其中 2 页和 1 页、再请求 4 页（应失败）与 1 页（应拿到尾部块），正是用来验证这种分裂/合并顺序的。

### 2.2 `page_init`：从 DTB 到空闲页链表

```c
static void page_init(void)
{
    va_pa_offset = PHYSICAL_MEMORY_OFFSET;

    uint64_t mem_base = get_memory_base();
    uint64_t mem_size = get_memory_size();
    if (mem_base == 0 || mem_size == 0) {
        panic("page_init: invalid physical memory range from DTB");
    }

    npage = PPN(mem_base + mem_size);
    extern char end[];
    pages = (struct Page *)ROUNDUP((uintptr_t)end, PGSIZE);

    for (size_t i = nbase; i < npage; i++) {
        struct Page *p = &pages[i - nbase];
        p->flags = 0;
        p->property = 0;
        set_page_ref(p, 0);
        SetPageReserved(p);
    }

    uintptr_t free_start_pa = PADDR(ROUNDUP((uintptr_t)(pages + (npage - nbase)), PGSIZE));
    uintptr_t free_end_pa = ROUNDDOWN(mem_base + mem_size, PGSIZE);

    if (free_start_pa < free_end_pa) {
        init_memmap(pa2page(free_start_pa), (free_end_pa - free_start_pa) / PGSIZE);
    } else {
        cprintf("page_init: no free page!\n");
    }
}
```

几个关键点：

- `va_pa_offset = PHYSICAL_MEMORY_OFFSET`，即 `0xFFFFFFFF40000000`；由于 `KERNBASE = 0xFFFFFFFFC0200000`，`PADDR(KERNBASE) = 0x80200000`，虚拟地址与物理地址之间只差这个常量。
- `npage = PPN(mem_base + mem_size)` 是物理内存顶端页号（含），`nbase = DRAM_BASE / PGSIZE = 0x80000`，所以 `Page` 数组长度为 `npage - nbase`，用 `pages[i - nbase]` 访问。
- `pages` 是**虚拟地址**，紧跟在链接符号 `end` 之后并按页对齐；`PADDR` 之后才是物理地址。`Page` 数组本身也属于内核占用内存，必须落在保留区里。
- 先把所有页标记 `PageReserved`，再开放空闲区。这样即使 `init_memmap` 之前的代码误用页分配器，也不会把内核镜像或 `Page` 数组分出去。
- 空闲区从 `Page` 数组末尾开始，到 `mem_base + mem_size` 向下对齐；两端的 `ROUNDUP`/`ROUNDDOWN` 保证不越界。

内存布局可以概括为：

```text
0x80000000 ┌───────────────────────────────┐
           │ OpenSBI / 内核镜像            │  ← 全部 PageReserved
end        ├───────────────────────────────┤
0x8020E000 │ struct Page 数组（约 2 MB）    │  ← 全部 PageReserved
free_start ├───────────────────────────────┤
           │ 空闲物理页（Best-Fit 链表）    │
0x88000000 └───────────────────────────────┘
```

### 2.3 `get_pte`：Sv39 三级页表遍历

`get_pte(pgdir, la, create)` 返回线性地址 `la` 对应页表项的内核虚拟地址；若中间页表不存在且 `create` 为真，则分配并清零一个页表页。`pgdir` 是顶层页表的**内核虚拟地址**。

```c
pte_t *get_pte(pde_t *pgdir, uintptr_t la, bool create)
{
    pde_t *pdep1 = &pgdir[PDX1(la)];
    if (!(*pdep1 & PTE_V)) {
        struct Page *page;
        if (!create || (page = alloc_page()) == NULL) {
            return NULL;
        }
        set_page_ref(page, 1);
        uintptr_t pa = page2pa(page);
        memset(KADDR(pa), 0, PGSIZE);
        *pdep1 = pte_create(page2ppn(page), PTE_U | PTE_V);
    }
    pde_t *pdep0 = &((pte_t *)KADDR(PDE_ADDR(*pdep1)))[PDX0(la)];
    if (!(*pdep0 & PTE_V)) {
        struct Page *page;
        if (!create || (page = alloc_page()) == NULL) {
            return NULL;
        }
        set_page_ref(page, 1);
        uintptr_t pa = page2pa(page);
        memset(KADDR(pa), 0, PGSIZE);
        *pdep0 = pte_create(page2ppn(page), PTE_U | PTE_V);
    }
    return &((pte_t *)KADDR(PDE_ADDR(*pdep0)))[PTX(la)];
}
```

这里 `PDX1(la) = (la >> 30) & 0x1FF` 是 Sv39 的 VPN[2]（顶层索引），`PDX0(la) = (la >> 21) & 0x1FF` 是 VPN[1]，`PTX(la) = (la >> 12) & 0x1FF` 是 VPN[0]。所以代码中的两段几乎相同的代码分别负责**分配第二级页表**和**分配第三级页表**；每个新页表页都要 `set_page_ref(1)`、清零、用 `pte_create` 写入“指向下一页表的 PTE”。

需要单独说明内核高地址的情况：内核自身运行在 `0xFFFFFFFFC0200000` 附近的 1 GB 巨页里，`boot_page_table_sv39[511]` 是一个**叶子**巨页项。对这类地址调用 `get_pte` 会把叶子项误当成“指向下一级页表的指针”，因此 Lab 4 只对低地址（如 `0x100`、`0x0`、`PGSIZE`）建立细粒度映射；内核高地址的映射由启动页表的巨页负责。这是本实验“够用即可”的简化，也是挑战题讨论巨页拆分时的切入点。

### 2.4 `page_insert` / `page_remove`：引用计数与 TLB

`page_insert` 的语义是“把物理页 `page` 映射到 `la`，权限为 `perm`”。它必须同时满足：旧映射被正确撤销、引用计数恰好加一、不出现半映射、TLB 不残留旧项。

```c
int page_insert(pde_t *pgdir, struct Page *page, uintptr_t la, uint32_t perm)
{
    pte_t *ptep = get_pte(pgdir, la, 1);
    if (ptep == NULL) {
        return -E_NO_MEM;
    }
    page_ref_inc(page);
    if (*ptep & PTE_V) {
        struct Page *p = pte2page(*ptep);
        if (p == page) {
            page_ref_dec(page);          // 同一页重映射，抵消多加的一次
        } else {
            page_remove_pte(pgdir, la, ptep);  // 先撤销旧映射
        }
    }
    *ptep = pte_create(page2ppn(page), PTE_V | perm);
    tlb_invalidate(pgdir, la);
    return 0;
}
```

顺序很重要：**先 `get_pte(create=1)` 再 `page_ref_inc`**。如果页表分配失败，函数直接返回 `-E_NO_MEM`，此时还没有修改任何映射，也不会多出一个引用。若旧映射存在，则先判断是否同一物理页：同一页时，`page_ref_inc` 已经加了一次，但“重映射”本身不增加新的引用关系，所以要把这次多余的引用减回来；不同页时，先 `page_remove_pte` 撤销旧映射（可能把旧页释放掉），再安装新 PTE。最后写 `pte_create(page2ppn(page), PTE_V | perm)`，并用 `sfence.vma` 刷新该地址的 TLB。

`page_remove_pte` 是两者的公共底层：

```c
static void page_remove_pte(pde_t *pgdir, uintptr_t la, pte_t *ptep)
{
    if (*ptep & PTE_V) {
        struct Page *page = pte2page(*ptep);
        if (page_ref_dec(page) == 0) {
            free_page(page);
        }
        *ptep = 0;
        tlb_invalidate(pgdir, la);
    }
}
```

注意 `pte2page` 内部会断言 `PTE_V`，所以必须先判断 `PTE_V` 再调用；`page_ref_dec` 返回**递减后**的引用计数，只有降到 0 才能释放物理页。`page_remove` 则用 `get_pte(pgdir, la, 0)` 做纯查找：

```c
void page_remove(pde_t *pgdir, uintptr_t la)
{
    pte_t *ptep = get_pte(pgdir, la, 0);
    if (ptep != NULL) {
        page_remove_pte(pgdir, la, ptep);
    }
}
```

`create = 0` 保证对未映射地址调用时不会顺带分配页表；`ptep == NULL`（页表尚未建立）与 `*ptep == 0`（页表存在但项为空）都被视为“本来就没映射”，直接返回。因此 `page_remove` 是幂等的，`test_lab4_pmm_basic` 中对 `2*PGSIZE` 连续调用两次不会 panic。

`check_pgdir` 的断言序列正好覆盖这些语义：

1. `page_insert(boot_pgdir_va, p1, 0x0, 0)` 后 `get_page` 能得到 `p1`，`page_ref(p1) == 1`。
2. 把 `p2` 映射到 `PGSIZE` 并带 `PTE_U | PTE_W`，再把 `p1` 重映射到 `PGSIZE` 且 `perm = 0`：`p1` 的引用变为 2（`0x0` 与 `PGSIZE` 两处映射），`p2` 的引用降为 0 并被释放，`PGSIZE` 处的 PTE 只剩 `PTE_V`（`U/W` 被清掉）。
3. 同一页 `p3` 连续两次映射到 `2*PGSIZE`，第二次带 `PTE_W`：引用仍为 1，`nr_free` 不变。
4. 依次 `page_remove` 三个地址，再对 `2*PGSIZE` 重复一次：所有引用归 0，无 panic。

### 2.5 `alloc_proc`：PCB 的初始化

`alloc_proc` 用 `kmalloc(sizeof(struct proc_struct))` 从 SLOB 堆取一块内存，然后逐字段初始化。最容易出错的是 `pgdir`：它必须是**物理地址**，因为 `proc_run` 会直接把它写进 `satp`。因此这里用 `boot_pgdir_pa`，而不是 `boot_pgdir_va`。`context` 清零后 `ra = 0`、`sp = 0`，这正是 `test_lab4_process_create` 对 `idleproc` 的断言；`idleproc` 真正开始运行后，这些字段会被 `switch_to` 写入真实值。

`tf = NULL` 也是断言的一部分：`idleproc` 不是“从 trapframe 返回”的线程，它的 `tf` 只有在创建子线程时才由 `copy_thread` 填写（那是子线程的 `tf`，不是 `idleproc` 自己的）。

### 2.6 `proc_init`：idleproc 与 initproc

```c
void proc_init(void)
{
    int i;
    list_init(&proc_list);
    for (i = 0; i < HASH_LIST_SIZE; i++) {
        list_init(hash_list + i);
    }

    if ((idleproc = alloc_proc()) == NULL) {
        panic("cannot alloc idleproc.\n");
    }
    idleproc->pid = 0;
    idleproc->state = PROC_RUNNABLE;
    idleproc->kstack = (uintptr_t)bootstack;
    idleproc->need_resched = 1;
    set_proc_name(idleproc, "idle");
    nr_process++;

    current = idleproc;

    int pid = kernel_thread(init_main, "Hello world!!", 0);
    if (pid <= 0) {
        panic("create init_main failed.\n");
    }
    initproc = find_proc(pid);
    set_proc_name(initproc, "init");

    assert(idleproc != NULL && idleproc->pid == 0);
    assert(initproc != NULL && initproc->pid == 1);
}
```

`idleproc` 是一个特殊的“包装”：它没有自己的内核栈（直接复用 `bootstack`），也不由 `do_fork` 创建；`kstack` 指向启动栈，`need_resched = 1` 让 `cpu_idle` 立刻让出 CPU。它**不插入 `proc_list`**，这样 `schedule` 的正常轮转只会在真实线程之间进行，只有“没有任何可运行线程”时才回退到它。

`initproc` 则完全走 `kernel_thread → do_fork → copy_thread` 的常规路径：`pid = 1`、`parent = idleproc`、`kstack` 为新分配的 2 页、`tf` 指向栈顶 trapframe、`context.ra = forkret`、`context.sp = tf`。此时它已经是 `PROC_RUNNABLE`，但还没被调度；`cpu_idle → schedule` 会选中它。

### 2.7 `kernel_thread` 与 `copy_thread`：伪造一次“陷阱返回”

新线程不能从函数中间“凭空开始”，它必须像“刚刚发生了一次陷阱、现在要返回”一样进入内核。Lab 4 的做法是手工构造一个 `trapframe`：

```c
int kernel_thread(int (*fn)(void *), void *arg, uint32_t clone_flags)
{
    struct trapframe tf;
    memset(&tf, 0, sizeof(struct trapframe));
    tf.gpr.s0 = (uintptr_t)fn;
    tf.gpr.s1 = (uintptr_t)arg;
    tf.status = (read_csr(sstatus) | SSTATUS_SPP | SSTATUS_SPIE) & ~SSTATUS_SIE;
    tf.epc = (uintptr_t)kernel_thread_entry;
    return do_fork(clone_flags | CLONE_VM, 0, &tf);
}
```

`entry.S` 中的 `kernel_thread_entry` 约定：`s0` 存函数指针，`s1` 存参数，它执行 `move a0, s1; jalr s0` 后调用 `do_exit`。因此这里把 `fn`、`arg` 放进 `s0`、`s1`，把 `epc` 指向 `kernel_thread_entry`。

`status` 的三个位各有含义：`SPP = 1` 让 `sret` 返回 S 态（内核线程运行在 S 态）；`SPIE = 1` 让 `sret` 之后 `SIE = 1`，即新线程开始执行时中断是打开的；构造期间先清掉 `SIE`，避免在 `do_fork` 尚未完成时被时钟中断打断。

`copy_thread` 负责把这份 `tf` 复制到新线程内核栈的**最高处**，并设置初始上下文：

```c
static void copy_thread(struct proc_struct *proc, uintptr_t esp, struct trapframe *tf)
{
    proc->tf = (struct trapframe *)(proc->kstack + KSTACKSIZE - sizeof(struct trapframe));
    *(proc->tf) = *tf;

    proc->tf->gpr.a0 = 0;                 // 子线程返回值为 0
    proc->tf->gpr.sp = (esp == 0) ? (uintptr_t)proc->tf : esp;
    proc->tf->gpr.s0 = tf->gpr.s0;
    proc->tf->gpr.s1 = tf->gpr.s1;

    proc->context.ra = (uintptr_t)forkret;
    proc->context.sp = (uintptr_t)(proc->tf);
}
```

为什么 `tf` 放在 `kstack + KSTACKSIZE - sizeof(tf)`？内核栈向低地址增长，栈顶是最高地址；把 `trapframe` 放在最顶端，既不会与栈上局部变量冲突，又能让 `RESTORE_ALL` 以 `sp = tf` 为基址逐项读取。`gpr.sp = tf` 还有一层含义：`RESTORE_ALL` 最后会把 `sp` 恢复成这个值，于是 `sret` 进入 `kernel_thread_entry` 时，`sp` 正好指向 trapframe 顶部，函数调用可以向低地址继续使用栈。

`context.sp = tf`、`context.ra = forkret` 则是给 `switch_to` 用的：第一次切换到该线程时，`switch_to` 恢复 `ra = forkret`、`sp = tf`，`ret` 跳入 `forkret`；`forkret` 调用 `forkrets(current->tf)`，后者 `move sp, a0; j __trapret`，把栈切到 trapframe 并直接进入 `RESTORE_ALL`。整条链路是：

```text
switch_to → ret → forkret → forkrets → __trapret → RESTORE_ALL → sret
          → kernel_thread_entry → move a0,s1; jalr s0 → fn(arg)
```

### 2.8 `do_fork`：创建线程的七步

`do_fork` 负责“复制一个执行流”，步骤与错误清理如下：

1. 检查 `nr_process < MAX_PROCESS`，否则返回 `-E_NO_FREE_PROC`。
2. `alloc_proc()` 分配 PCB；失败返回 `-E_NO_MEM`。
3. `proc->parent = current`。
4. `setup_kstack(proc)` 分配 2 页内核栈并记录 `kstack`。
5. `copy_mm(clone_flags, proc)`：Lab 4 只创建内核线程，`current->mm == NULL`，函数只做断言并返回 0。
6. `copy_thread(proc, stack, tf)`：填写 `tf` 与 `context`。
7. 在关中断的临界区内完成 `pid = get_pid()`、`hash_proc`、`list_add(&proc_list, &proc->list_link)`、`nr_process++`；最后 `wakeup_proc(proc)` 把状态从 `PROC_UNINIT` 改为 `PROC_RUNNABLE`，返回 `pid`。

错误路径必须按相反顺序释放资源：`bad_fork_cleanup_kstack` 调 `put_kstack`，`bad_fork_cleanup_proc` 调 `kfree`，最后回到 `fork_out`。临界区的意义在于：`get_pid` 的分配、哈希表插入与 `proc_list` 插入必须是一个原子整体，否则时钟中断可能在“pid 已分配但链表未插入”的中间状态触发调度，导致 `find_proc` 找不到线程。

### 2.9 `schedule`：FIFO 轮转与 idle 兜底

```c
void schedule(void)
{
    bool intr_flag;
    list_entry_t *le, *last;
    struct proc_struct *next = NULL;

    local_intr_save(intr_flag);
    {
        current->need_resched = 0;
        last = (current == idleproc) ? &proc_list : &(current->list_link);
        le = last;
        do {
            if ((le = list_next(le)) != &proc_list) {
                next = le2proc(le, list_link);
                if (next->state == PROC_RUNNABLE) {
                    break;
                }
            }
        } while (le != last);

        if (next == NULL || next->state != PROC_RUNNABLE) {
            next = idleproc;
        }
        next->runs++;
        if (next != current) {
            proc_run(next);
        }
    }
    local_intr_restore(intr_flag);
}
```

选择策略是“从当前线程的下一个开始，沿 `proc_list` 找第一个 `PROC_RUNNABLE`，绕一圈仍找不到就回到 `idleproc`”。`last` 的作用是记录起点，防止在“只有当前线程可运行”时死循环；由于 `idleproc` 不在链表里，`current == idleproc` 时起点直接设为链表头。`runs++` 记录被选中次数，`next != current` 时才真正切换，避免无意义的上下文保存/恢复。

### 2.10 `proc_run` 与 `switch_to`：地址空间与寄存器上下文

```c
void proc_run(struct proc_struct *proc)
{
    if (proc != current) {
        bool intr_flag;
        struct proc_struct *prev = current, *next = proc;
        local_intr_save(intr_flag);
        {
            current = proc;
            write_csr(satp, 0x8000000000000000 | (proc->pgdir >> RISCV_PGSHIFT));
            flush_tlb();
            switch_to(&(prev->context), &(next->context));
        }
        local_intr_restore(intr_flag);
    }
}
```

`satp` 的高 4 位是模式：8 表示 Sv39；低 44 位是顶层页表的物理页号，所以写 `0x8000000000000000 | (pgdir >> 12)`。切换页表后必须 `sfence.vma`，否则 TLB 中可能残留旧地址空间的映射。`switch_to` 只保存/恢复 callee-saved 寄存器：

```asm
switch_to:
    STORE ra, 0*REGBYTES(a0)
    STORE sp, 1*REGBYTES(a0)
    STORE s0, 2*REGBYTES(a0)
    ...
    STORE s11, 13*REGBYTES(a0)

    LOAD ra, 0*REGBYTES(a1)
    LOAD sp, 1*REGBYTES(a1)
    LOAD s0, 2*REGBYTES(a1)
    ...
    LOAD s11, 13*REGBYTES(a1)
    ret
```

`struct context` 的字段顺序必须与汇编中的偏移严格一致：`ra, sp, s0, …, s11`。只保存 callee-saved 寄存器是 RISC-V ABI 的直接推论：`switch_to` 是一个普通函数调用，调用者已经把 `t0`–`t6`、`a0`–`a7` 等 caller-saved 寄存器视为“可被破坏”，不需要由被调用者保存；而 `s0`–`s11`、`sp`、`ra` 是跨调用需要保持的，所以必须显式保存。`ret` 使用的是从 `to` 恢复出的 `ra`，因此第一次切换会跳到 `forkret`，之后的切换则回到 `proc_run` 中 `switch_to` 的下一条指令。

### 2.11 中断/异常回填：`RESTORE_ALL` 与处理函数

RESTORE_ALL 的顺序必须与 SAVE_ALL 对应：

```asm
.macro RESTORE_ALL
    LOAD s1, 32*REGBYTES(sp)
    csrw sstatus, s1
    LOAD s2, 33*REGBYTES(sp)
    csrw sepc, s2
    LOAD x1, 1*REGBYTES(sp)
    LOAD x3, 3*REGBYTES(sp)
    ...
    LOAD x31, 31*REGBYTES(sp)
    LOAD x2, 2*REGBYTES(sp)     # sp 最后恢复
.endm
```

先恢复 `sstatus`、`sepc`，再恢复通用寄存器；`sp` 必须**最后**恢复，因为前面所有 `LOAD` 都以它为基址。`x0` 不需要恢复（硬连线为 0）。`__alltraps` 只需把 `sp` 作为 `tf` 参数传给 `trap`：

```asm
__alltraps:
    SAVE_ALL
    move a0, sp
    jal trap
__trapret:
    RESTORE_ALL
    sret
```

处理函数方面，Lab 3 的代码可以直接复用，但要去掉 Lab 4 不存在的 `SHUTDOWN_AFTER` 与 `sbi_shutdown`：

```c
static inline uintptr_t insn_length(uintptr_t epc)
{
    uint16_t insn = *(volatile uint16_t *)epc;
    return ((insn & 0x3) == 0x3) ? 4 : 2;
}

void interrupt_handler(struct trapframe *tf)
{
    intptr_t cause = (tf->cause << 1) >> 1;
    switch (cause) {
    case IRQ_S_SOFT:
        cprintf("Supervisor software interrupt\n");
        break;
    case IRQ_S_TIMER:
        clock_set_next_event();      // 先重新装载，否则只会收到一次时钟中断
        ticks++;
        if (ticks % TICK_NUM == 0) {
            print_ticks();
        }
        break;
    default:
        print_trapframe(tf);
        break;
    }
}
```

`insn_length` 用于异常返回时跳过出错指令：RISC-V 指令可能是 2 字节压缩指令或 4 字节标准指令，低两位不是 `0b11` 就是 2 字节。如果硬编码 4，会跳过压缩指令的后半部分或下一条指令，导致程序跑飞。

### 4.2 `page_insert` 对同一物理页重复映射时引用计数多加一次

- **症状（审查阶段发现）**：按“先 `page_ref_inc`，再无条件 `page_remove_pte` 旧映射”的写法，`test_lab4_pmm_basic` 中 `p3` 连续两次映射到 `2*PGSIZE` 后 `page_ref(p3)` 会变成 2，而测试断言为 1；`check_pgdir` 里 `p1` 的重映射也会多一次引用。
- **原因**：`page_ref_inc` 是“新增一条映射”的引用；当旧 PTE 指向的正是同一个物理页时，旧映射并不是一条独立的引用，撤销它不能减少引用；先加后减若条件写错，就会多算一次。
- **修复**：先 `page_ref_inc(page)`，再判断旧 PTE：`p == page` 时只做 `page_ref_dec(page)` 抵消本次多加的引用；`p != page` 时才调用 `page_remove_pte` 真正撤销旧映射。这样同一页重复映射的净效果是引用不变（仍为 1）。
- **验证**：`check_pgdir` 的 `page_ref(p1) == 2`、`page_ref(p2) == 0`、`page_ref(p3) == 1` 全部成立。

### 4.3 `page_remove` 在未映射地址上分配页表或触发 `pte2page` 断言

- **症状（审查阶段发现）**：初版把 `page_remove` 写成 `get_pte(pgdir, la, 1)`，再直接 `pte2page(*ptep)`。这样对 `2*PGSIZE` 第二次 `page_remove` 时，PTE 已被清空，`pte2page` 内部 `assert(*ptep & PTE_V)` 会失败并 panic；对完全未映射的地址还会顺带分配两级页表。
- **原因**：`get_pte` 的 `create` 参数被忽略；`pte2page` 的前置条件是 PTE 有效。
- **修复**：`page_remove` 使用 `get_pte(pgdir, la, 0)`；`page_remove_pte` 内部先判断 `*ptep & PTE_V`，无效直接返回。这样“页表不存在”和“页表存在但项为空”都成为无操作。
- **验证**：测试对 `2*PGSIZE` 连续两次 `page_remove` 不 panic，所有引用归 0，`nr_free` 回到初值。

### 4.4 `alloc_proc` 把 `boot_pgdir_va` 写进 `pgdir`

- **症状（审查阶段发现）**：如果按初版把 `boot_pgdir_va` 赋给 `pgdir`，`test_lab4_process_create` 可能仍能通过（它不直接检查 `pgdir` 的数值），但第一次 `proc_run` 切换 `satp` 后会取指异常或立刻跑飞，串口在 `++ setup timer interrupts` 之后没有 `initproc` 输出。

## 五、练习解答

### 5.1 练习一：`page_insert` / `page_remove`

```c
static void page_remove_pte(pde_t *pgdir, uintptr_t la, pte_t *ptep)
{
    if (*ptep & PTE_V) {
        struct Page *page = pte2page(*ptep);
        if (page_ref_dec(page) == 0) {
            free_page(page);
        }
        *ptep = 0;
        tlb_invalidate(pgdir, la);
    }
}

int page_insert(pde_t *pgdir, struct Page *page, uintptr_t la, uint32_t perm)
{
    pte_t *ptep = get_pte(pgdir, la, 1);
    if (ptep == NULL) {
        return -E_NO_MEM;
    }
    page_ref_inc(page);
    if (*ptep & PTE_V) {
        struct Page *p = pte2page(*ptep);
        if (p == page) {
            page_ref_dec(page);
        } else {
            page_remove_pte(pgdir, la, ptep);
        }
    }
    *ptep = pte_create(page2ppn(page), PTE_V | perm);
    tlb_invalidate(pgdir, la);
    return 0;
}

void page_remove(pde_t *pgdir, uintptr_t la)
{
    pte_t *ptep = get_pte(pgdir, la, 0);
    if (ptep != NULL) {
        page_remove_pte(pgdir, la, ptep);
    }
}
```

设计要点：

- **失败原子性**：`get_pte(create=1)` 在写入任何 PTE 之前完成页表分配；失败直接返回，不会出现“映射了一半”的状态。
- **引用计数**：映射建立时 `page_ref_inc`，撤销时 `page_ref_dec`；只有引用降到 0 才 `free_page`，防止仍被其他地址映射的页被回收。
- **同页重映射**：`p == page` 时不撤销旧 PTE，只抵消本次多加的引用；随后覆盖 PTE 的权限。
- **TLB**：每次修改 PTE 后 `sfence.vma la`，保证下一次访问看到新映射。
- **幂等**：`page_remove` 不分配页表、空 PTE 直接跳过，重复调用安全。

### 5.2 练习二：进程创建

```c
static struct proc_struct *alloc_proc(void)
{
    struct proc_struct *proc = kmalloc(sizeof(struct proc_struct));
    if (proc != NULL) {
        proc->state = PROC_UNINIT;
        proc->pid = -1;
        proc->runs = 0;

        proc->need_resched = 0;

        proc->mm = NULL;
        memset(&(proc->context), 0, sizeof(struct context));
        proc->tf = NULL;
        proc->pgdir = boot_pgdir_pa;
        proc->flags = 0;
        memset(proc->name, 0, PROC_NAME_LEN + 1);
    }
    return proc;
}

static int copy_mm(uint32_t clone_flags, struct proc_struct *proc)
{
    (void)clone_flags;
    (void)proc;
    assert(current->mm == NULL);
    return 0;
}

static void copy_thread(struct proc_struct *proc, uintptr_t esp, struct trapframe *tf)
{
    proc->tf = (struct trapframe *)(proc->kstack + KSTACKSIZE - sizeof(struct trapframe));
    *(proc->tf) = *tf;
    proc->tf->gpr.a0 = 0;
    proc->tf->gpr.sp = (esp == 0) ? (uintptr_t)proc->tf : esp;
    proc->tf->gpr.s0 = tf->gpr.s0;
    proc->tf->gpr.s1 = tf->gpr.s1;
    proc->context.ra = (uintptr_t)forkret;
    proc->context.sp = (uintptr_t)(proc->tf);
}

int kernel_thread(int (*fn)(void *), void *arg, uint32_t clone_flags)
{
    struct trapframe tf;
    memset(&tf, 0, sizeof(struct trapframe));
    tf.gpr.s0 = (uintptr_t)fn;
    tf.gpr.s1 = (uintptr_t)arg;
    tf.status = (read_csr(sstatus) | SSTATUS_SPP | SSTATUS_SPIE) & ~SSTATUS_SIE;
    tf.epc = (uintptr_t)kernel_thread_entry;
    return do_fork(clone_flags | CLONE_VM, 0, &tf);
}
```

`do_fork` 与 `proc_init` 的完整实现见 2.6、2.8 节。关键是：

- `alloc_proc` 只做“静态初始化”，`pid`、`kstack`、`tf`、`context` 分别在 `do_fork`、`setup_kstack`、`copy_thread` 中填写。
- `copy_mm` 在 Lab 4 中必须保持“占位”语义：内核线程没有用户地址空间，`current->mm` 为 `NULL`；如果在这里尝试复制页表，会解引用空指针。
- `proc_init` 中 idleproc 的 `need_resched = 1` 是启动调度的“发令枪”：`cpu_idle` 第一次循环就会让出 CPU。
- `do_fork` 的 `wakeup_proc` 把状态从 `PROC_UNINIT` 改为 `PROC_RUNNABLE`，因此新线程创建后即可被 `schedule` 选中。

### 5.3 练习三：调度、切换与 idle

```c
void cpu_idle(void)
{
    while (1) {
        if (current->need_resched) {
            schedule();
        }
    }
}

void proc_run(struct proc_struct *proc)
{
    if (proc != current) {
        bool intr_flag;
        struct proc_struct *prev = current, *next = proc;
        local_intr_save(intr_flag);
        {
            current = proc;
            write_csr(satp, 0x8000000000000000 | (proc->pgdir >> RISCV_PGSHIFT));
            flush_tlb();
            switch_to(&(prev->context), &(next->context));
        }
        local_intr_restore(intr_flag);
    }
}
```

`schedule` 的完整代码见 2.9 节。四者的分工可以概括为：

| 函数 | 职责 | 关键点 |
| --- | --- | --- |
| `cpu_idle` | idleproc 的主循环 | 检查 `need_resched`，主动让出 CPU |
| `schedule` | 选择下一个线程 | FIFO 扫描、idle 兜底、临界区、`runs++` |
| `proc_run` | 切换地址空间并调用上下文切换 | 写 `satp`、`flush_tlb`、`switch_to` |
| `switch_to` | 保存/恢复寄存器上下文 | 只动 callee-saved，`ret` 跳到新 `ra` |

`switch_to` 的完整汇编见 2.10 节。第一次切换时，`idleproc->context.ra` 是 `switch_to` 的返回地址（保存在 `proc_run` 栈帧中），`initproc->context.ra` 是 `forkret`；因此 `ret` 会进入 `forkret`，而不是回到 `proc_run` 的下一条指令。这个差异正是“新线程第一次运行”的实现方式。

## 六、知识点与 OS 原理的对应

### 6.1 实现点与原理对照

| 实现点 | 对应知识点 | 原理说明 |
| --- | --- | --- |
| `default_init_memmap` / Best-Fit | 物理内存管理、空闲链表 | 用 `Page` 数组描述物理页，空闲块按地址有序组织；分配选最小合适块，释放时合并相邻块，减少外部碎片 |
| `page_init` 的 `PageReserved` | 内存布局、内核保留区 | 内核镜像、`Page` 数组、OpenSBI 不能被分配；先全部保留再开放空闲区，避免“分配器管理自己正在使用的内存” |
| `get_pte` 三级遍历 | Sv39 分页、页表自映射 | VPN[2]/VPN[1]/VPN[0] 分别索引三级页表；非叶子 PTE 指向下一级页表的物理页 |
| `pte_create(ppn, perm)` | PTE 编码、权限位 | PPN 左移 10 位，低位放 V/R/W/X/U/A/D；硬件在访问时检查权限并更新 A/D |
| `page_insert` 引用计数 | 物理页生命周期 | 一条映射持有一个引用；同一页多映射时引用累加；最后一个引用消失才可回收 |
| `page_remove` 幂等 | 页表撤销、异常安全 | 未映射地址不应分配页表，也不应触发断言；重复撤销是合法的 |
| `tlb_invalidate` | TLB 一致性 | 修改 PTE 后必须 `sfence.vma`，否则 CPU 可能继续使用旧翻译 |
| `alloc_proc` / `proc_init` | PCB、进程状态机 | `PROC_UNINIT → PROC_RUNNABLE → PROC_RUNNING → PROC_ZOMBIE`；idle 是特殊的内核线程 |
| `copy_thread` 伪造 `trapframe` | 上下文、陷阱返回 | 新线程的“初始状态”就是一份 trapframe；`sret` 从 `sepc` 开始执行，从 `sstatus` 恢复中断状态 |
| `do_fork` 临界区 | 并发、原子性 | pid 分配、哈希插入、链表插入必须原子，否则中断可能看到不一致的进程表 |
| `schedule` FIFO | 调度策略 | 简单轮转，保证公平性；idle 兜底保证没有可运行线程时仍有执行流（idle 本身忙等） |
| `switch_to` 只存 callee-saved | ABI、上下文切换 | 调用者已保存 caller-saved；被调用者只需保证 `s0`–`s11`、`sp`、`ra` 跨调用不变 |
| `proc_run` 写 `satp` | 地址空间切换 | 每个进程有独立页表；内核线程共享内核页表；切换后必须刷新 TLB |

### 6.2 指导书未覆盖或未展开的知识点

1. **用户态与 ELF 加载**：Lab 4 只创建内核线程，`copy_mm` 是占位；真实进程需要解析 ELF、建立用户页表、切换 U/S 态，并在 `sret` 前设置 `sstatus.SPP = 0`。
2. **VMA 与缺页异常**：`vmm.c` 已给出 `mm_struct`/`vma_struct`，但 `check_pgfault` 被注释；完整实现需要在 `CAUSE_LOAD_PAGE_FAULT`/`STORE_PAGE_FAULT` 中查 VMA、分配物理页并 `page_insert`。
3. **写时复制（COW）**：`do_fork` 目前只创建内核线程；若复制用户地址空间，需要把父进程页表设为只读，在写缺页时复制物理页并调整引用计数。
4. **SMP 与锁**：`local_intr_save/restore` 只能屏蔽本 CPU 中断；多核环境下进程表、`nr_process`、`get_pid` 需要自旋锁或原子操作。
5. **ASID 与 TLB shootdown**：`satp` 的 ASID 字段可以让不同进程的 TLB 项共存；当前每次切换都 `flush_tlb()`，代价较高。多核修改页表后还需要 IPI 通知其他 CPU 刷新 TLB。
6. **巨页拆分**：`boot_page_table_sv39` 用 1 GB 巨页映射内核；若要对其中的 4 KB 区域做细粒度权限控制，需要把巨页拆成 512 个页表项并刷新 TLB。
7. **内核栈溢出与保护页**：`KSTACKPAGE = 2` 只有 8 KB，深递归或大局部变量会踩到 trapframe；生产内核通常加 guard page 或使用独立中断栈。
8. **内存分配器**：`kmalloc` 是简化的 SLOB，只有单向空闲链表；真实内核需要 slab/slub、per-CPU 缓存与碎片整理。

## 七、思考题与扩展

### 7.1 `local_intr_save/restore` 如何实现关中断与恢复

`kern/sync/sync.h` 的实现是：

```c
static inline bool __intr_save(void) {
    if (read_csr(sstatus) & SSTATUS_SIE) {
        intr_disable();
        return 1;
    }
    return 0;
}

static inline void __intr_restore(bool flag) {
    if (flag) {
        intr_enable();
    }
}
```

`intr_disable()` 执行 `clear_csr(sstatus, SSTATUS_SIE)`，`intr_enable()` 执行 `set_csr(sstatus, SSTATUS_SIE)`。关键在于：`__intr_save` 返回的是“进入临界区之前中断是否已经打开”，而不是无条件关中断。这样嵌套使用时，内层 `restore` 不会错误地打开外层仍然希望保持关闭的中断——只有最外层保存的 `flag` 为真，才会真正开中断。

在 `schedule` 与 `proc_run` 中，临界区保护的是 `proc_list`、`current`、`satp` 与 `switch_to` 的一致性：如果时钟中断在“`current` 已改、`satp` 未改”或“链表正在插入”时到来，调度器可能看到半个状态。`switch_to` 执行期间中断必须关闭，因为此时两个线程的栈都在使用中，任何中断都可能把新的 trapframe 写到错误的栈上。

### 7.2 Sv32 / Sv39 / Sv48 的差异

| 项目 | Sv32 | Sv39 | Sv48 |
| --- | --- | --- | --- |
| 虚拟地址宽度 | 32 位 | 39 位 | 48 位 |
| 页表级数 | 2 | 3 | 4 |
| 每级索引位数 | 10 / 10 | 9 / 9 / 9 | 9 / 9 / 9 / 9 |
| PTE 大小 | 4 字节 | 8 字节 | 8 字节 |
| 物理地址宽度 | 34 位 | 56 位 | 56 位 |
| `satp` 模式 | 1 | 8 | 9 |
| 单页大小 | 4 KB | 4 KB | 4 KB |
| 大页支持 | 4 MB | 2 MB / 1 GB | 2 MB / 1 GB / 512 GB |

Lab 4 运行在 Sv39 下：`PDX1`、`PDX0`、`PTX` 各 9 位，`get_pte` 的三级遍历对应 Sv39 的 VPN[2]、VPN[1]、VPN[0]。Sv32 只需两级，Sv48 需要四级；如果把 `get_pte` 扩展到 Sv48，需要再增加一层 `PDX2` 索引与一次页表分配。

### 7.3 `get_pte` 中两段相似代码的成因与拆分建议

两段代码分别处理：

1. `pgdir[PDX1(la)]` 无效 → 分配**第二级页表**（level-1 table），把它的物理页号写入顶层 PTE。
2. `pdep0`（第二级表中的项）无效 → 分配**第三级页表**（level-0 table），把它的物理页号写入第二级 PTE。

之所以看起来“完全一样”，是因为两者都执行“分配一个清零页、`set_page_ref(1)`、写入 `PTE_U | PTE_V`”这套动作；区别只在操作的是哪一级指针。这种重复在 Sv32 中只会出现一次（只有两级），在 Sv48 中会出现三次，所以更适合抽成辅助函数：

```c
static pte_t *alloc_pt_page(void) {
    struct Page *page = alloc_page();
    if (page == NULL) return NULL;
    set_page_ref(page, 1);
    memset(KADDR(page2pa(page)), 0, PGSIZE);
    return page;
}
```

更重要的拆分是“查找”与“分配”：`get_pte(pgdir, la, create)` 目前用一个 `create` 参数同时承担两种语义，`page_remove` 必须记得传 `0`，否则会分配页表。更清晰的接口是：

```c
pte_t *walk_pte(pde_t *pgdir, uintptr_t la);          // 纯查找，不分配
pte_t *get_pte_for_write(pde_t *pgdir, uintptr_t la); // 查找并分配，返回错误码
```

这样 `page_remove`、`get_page` 使用 `walk_pte`，`page_insert` 使用 `get_pte_for_write`，调用点不需要记住 `create` 的含义。当前实现还有一个可改进点：如果第二级页表已分配、第三级分配失败，`get_pte` 会留下一个空的第二级页表（内存泄漏，但不是半映射）；严格实现应在失败时回收刚分配的页表页，或先完成所有分配再写入指针。

### 7.4 巨页映射与重映射

启动页表用 1 GB 巨页映射内核，好处是只需要一个 PTE 就能覆盖内核镜像、`Page` 数组和内核栈，启动阶段不必逐页建表；代价是巨页内的所有地址共享同一组权限，无法对某个 4 KB 区域单独设只读或不可执行。若要对内核某段做细粒度保护，需要：

1. 分配一个 4 KB 页表页，填入 512 个指向 4 KB 页的 PTE；
2. 用这个页表页的物理页号替换顶层巨页 PTE，并设置 `PTE_V`（非叶子项不设 R/W/X）；
3. `sfence.vma` 刷新整个地址范围。

Lab 4 的 `page_insert` 不能直接用于内核高地址，正是因为 `get_pte` 会把巨页叶子项误当成“指向下一级页表的指针”。这是本实验的简化边界，也是理解“页表遍历必须知道当前层级是否为叶子”的一个好例子。
